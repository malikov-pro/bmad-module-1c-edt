# e1c-review — ревью на чтение

**Позиция:** это линза для существующего ревью-процесса BMAD (`bmad-code-review`), не замена ему: процесс ведёт BMAD, здесь — доменная методика сбора доказательств и рубрика для 1С.

**Кросс-ревью вторым агентом:** ревью выполняет другая сессия/агент, не тот, кто строил изменение. Если выяснилось, что текущая сессия — авторская (тот же контекст сборки), откажись от саморевью: передай ревью новой сессии/агенту либо зафиксируй в отчёте ограничение «саморевью, вторая сторона отсутствует». Автор сам себя не ревьюит.

Требует `e1c-core`; рубрика ссылается на `e1c-bsl-practices`, `e1c-metadata-forms`, `e1c-testing-yaxunit` как нормативку по именам разделов — без пересказа их правил.

## 1. Граница режима: только чтение

Ревью выполняется в пресете **Analysis Only** сервера EDT-MCP (видимость инструментов урезана до read-only; включается на стороне плагина пользователем/конфигурацией — скилл её сам не переключает).

- Первый шаг ревью — зафиксировать фактическую видимость: есть ли в схеме инструментов пишущие вызовы (`write_module_source`, `create_metadata`, …). Есть → работай только read-инструментами, а в раздел «Границы ревью» отчёта добавь рекомендацию включить Analysis Only (least privilege).
- Просьбы «заодно поправь» — **отказ** с передачей в build-контур: правка другим контуром (build) с полным гейтом ядра. Ревьюер не смешивает роли.
- Операции над ИБ (прогоны тестов, обновления) ревьюер не инициирует: он работает с уже собранными доказательствами.

## 2. Сбор доказательств (read-only)

Вход: перечень затронутых объектов из стори/отчёта build (FQN, модули, формы). Если перечень неполон — восстанови его из diff ветки **как ориентир**: diff читается с диска без `resync_to_disk` (он недоступен в read-only), поэтому всё собранное с диска считается указателем, а доказательством становятся только данные, подтверждённые read-инструментами EDT-MCP.

| Что собрать | Чем |
|---|---|
| Ошибки EDT по затронутым объектам | `get_project_errors` (фильтры проект/серьёзность), свод — `get_problem_summary` |
| Код изменённых методов целиком, с контекстом | `read_method_source`, структура модуля — `get_module_structure` |
| Метаданные: свойства, члены, состав | `get_metadata_properties`, `get_metadata_details`, `list_subsystems`/`get_subsystem_content` |
| Формы | `get_form_layout_snapshot` («после»); состояние «до» — из отчёта build (snapshot перед правкой по `e1c-metadata-forms`) или из diff как ориентир |
| Использование затронутых top-level объектов | `find_references` |
| Текстовый поиск по коду (маркеры изменений, паттерны запросов, следы копипасты вместо переиспользования) | `search_in_code` |

Чего сбор **не** включает: запись, запуск тестов, обновление ИБ, правки файлов исходников.

Свежесть доказательств: ошибки EDT и результаты тестов должны быть получены **после последнего изменения** под ревью. Доказательство старше изменения = его нет.

## 3. Рубрика проверки

Проходи по пунктам, каждый вывод ссылается на раздел нормативки по имени:

1. **Стандарты BSL** — запрещённые конструкции, именование, комментарии, регионы, запросы (pre-flight и жёсткие запреты), транзакции/блокировки, клиент/сервер и асинхронность, привилегированный режим, журналирование, переиспользование перед написанием, доступ к данным через точку и производительность → `e1c-bsl-practices` (соответствующие разделы).
2. **Метаданные и формы** — изменения только инструментами (нет следов ручных правок `.mdo`/`Form.form`: чужие UUID, сдвинутые элементы), состав формы соответствует состоянию «до» плюс задача → `e1c-metadata-forms`.
3. **Расширения** — корректность перехватчиков (`ПродолжитьВызов` на месте, маркеры изменений присутствуют), extension-first для типового кода → `e1c-bsl-practices → Расширения`.
4. **Билингвальность** — ключ адресации Name, синонимы заполнены по каждому коду языка, синоним не используется как ключ → `e1c-core`.
5. **Изоляция тестов** — `.ВТранзакции()`/исключения а–в с teardown, zero-residue (коллектор, физическое удаление) → `e1c-testing-yaxunit` §4–§5.
6. **Полнота покрытия AC** — новые поведенческие требования стори покрыты новыми тестами YAxUnit; изменение прод-кода без соответствующих новых/изменённых тестов (когда AC этого требуют) — находка.
7. **Гейты ядра соблюдены автором** — деструктивные операции прошли preview→confirm, ИБ-операции в санкционированном канале. Источник: отчёт build/логи контура; проверить не удалось → пометь находку «не верифицируемо», не считай автоматически выполненным → `e1c-core`.

Находка без указания нарушенного правила или без цитаты строки — не находка, а мнение.

## 4. Вердикт по «зелёному»

Критерий done стори: ошибки EDT по затронутым объектам чистые **и** тесты YAxUnit прошли. Ревьюер:

- сверяет `get_project_errors` именно с затронутым перечнем (не «весь проект пуст») и оценивает свежесть картины: в read-only режиме запустить перепровалидацию нельзя — если известно об изменениях после последней валидации, картина устарела и вердикт «не подтверждён»;
- берёт результат прогона тестов из отчёта build (селектор, выполнено/упало/пропущено; ноль выполненных = неопределённый результат);
- при недостающих доказательствах (нет отчёта build, тесты не гонялись, ошибки недоступны) — вердикт **«не подтверждён»** с указанием, какого доказательства не хватает; импровизировать «скорее всего зелёное» запрещено.

Соотношение серьёзностей и вердикта:

- `blocker` — ломает критерий done или безопасность → done **не подтверждён**.
- `major` — нарушение правила, требует правки; сам по себе done не отменяет, но все `major` перечисляются в отчёте как обязательная правка (fix-forward).
- `minor` — замечание, без влияния на done.

## 5. Формат отчёта

```markdown
## Ревью <стори/FQN>: <дата>

### Находки
| # | Серьёзность | Правило | Место | Цитата/факт |
|---|---|---|---|---|
| 1 | major | e1c-bsl-practices → Запрещённые конструкции | Documents/Order/ObjectModule.bsl:42 | `Сообщить(...)` |

### Вердикт «зелёного»
Ошибки EDT: <чисто по затронутым / перечень; свежесть>. Тесты: <из отчёта build; селектор; выполнено/упало/пропущено>. Done: <подтверждён | не подтверждён — чего не хватает>.

### Границы ревью
Analysis Only: <да | нет — пишущие инструменты видимы, не использовались; рекомендация включить>.
Запись в конфигурацию не выполнялась. Прогоны/обновления ИБ не инициировались.
Кто ревьюил: <отдельная сессия | саморевью — ограничение>.
```
