## Интеграция слоёв

### Q1. Владение корневым `AGENTS.md` — конфликт двух установщиков
- **Суть:** BMAD-инсталлятор и ai_rules_1c оба управляют корневым `AGENTS.md`. Миграция ai_rules_1c переименовывает чужой `AGENTS.md` в `.bak.md` и инлайнит содержимое в `USER-RULES.md` между маркерами — точка входа BMAD может потеряться.
- **Варианты:**
  - A: сначала `1c-rules init`, затем BMAD install дописывает свой блок;
  - B: BMAD первым, ссылки на 1С-правила через `@-imports` в `USER-RULES.md`.
- **Статус:** открыт · 2026-08-24

### Q2. Где ссылка на EDT-MCP `rules/<lang>/INDEX.md`
- **Суть:** принятое ранее решение «вписать внутрь корневого `AGENTS.md`» рискованно: файл installer-managed и перезаписывается при update (пока не изменён пользователем). В `USER-RULES.md` есть документированный механизм `@-import` supplementary-файлов, и этот файл установщик **никогда** не перезаписывает.
- **Кандидат:** `@`-ссылка в `USER-RULES.md` вместо правки `AGENTS.md`. Зафиксировать уточнение к решению.
- **Статус:** открыт · 2026-08-24

### Q3. Граница L1/L2 — что берём у SteelMorgan после находок
- **Суть:** SDD (OpenSpec workspace ставится установщиком ai_rules_1c + `sdd-integrations.md`) и тиринг моделей (`/economymode`, `SUBAGENT_MODEL_*`, `subagent-pipeline.md`) уже есть в L1. У SteelMorgan берём строго то, чего нет в L1: песочница (docker/виртуалка), кросс-ревью вторым агентом, политики изоляции тестов (`yaxunit-isolation`, `vanessa-*`, `test-zero-residue`). Его coding-standards не берём (дубль L1), тиринг — проверить на дубль с `/economymode`.
- **Статус:** открыт · 2026-08-24

### Q4. Кто ставит гейт «ИБ только через EDT»
- **Суть:** текст гейта → `USER-RULES.md` (установщик его не перезаписывает), маркер `IB_UPDATE_CHANNEL=edt-only` → дописать в `.dev.env` (чужие ключи установщик сохраняет). Открыто: кто выполняет — setup-скилл модуля или инструкция агенту; финальная формулировка текста гейта (запрет `/update1cbase` и пакетного Designer вне CI-пайплайна, недоступного агенту интерактивно).
- **Статус:** открыт · 2026-08-24

## Решения и следующие за ними задачи

### Q9. Состав L1: из ai_rules_1c — только EDT-совместимое; его MCP-серверы — отдельными задачами
- **Решение (2026-08-24):** из ai_rules_1c в модуль берём то, что может использоваться с EDT (edt-workflow ветка, BSL-правила, субагенты, дисциплина памяти). Его собственный MCP-комплект (`1c-graph-metadata-mcp`, `1c-code-metadata-mcp`, `1C-docs-mcp`, `1c-syntax-checker-mcp`, `1c-templates-mcp`) признаётся **более функциональным**, чем аналоги, и подключается позже: пользователь формирует функционал MCP-серверов отдельными задачами и дополняет текущий проект наработками ai_rules_1c.
- **Открытые подпункты:**
  - порядок фаз: какие серверы первыми (кандидат: syntax-checker для верификации, graph/code-metadata для поиска);
  - влияние на цепочку верификации: сейчас «зелёный» = ошибки EDT (`get_project_errors`, `revalidate_objects`) + YAxUnit; с подключением серверов добавляется `syntaxcheck → check_1c_code → review_1c_code` из L1 — зафиксировать, какой слой чем владеет на каждом этапе;
  - стыковка с `mcp-first-search.md` (маршрутизация поиска index-MCP ↔ EDT-MCP) в `edt-workflow.md`.
- **Статус:** решение принято, реализация — отдельными задачами · 2026-08-24

## Открытые вопросы плана модуля (Phase 2, из `skills/reports/module-plan-1c-edt.md`)

### Q5. Подтвердить модель «прослойка стека» как архитектуру MVP
- **Решение (2026-08-24):** подтверждаю. Модуль — прослойка учёта стека «1С + EDT + EDT-MCP» внутри BMAD, по аналогии с тем, как BMAD учитывает стек через архитектуру и `AGENTS.md` / project-context. Методология (PRD → stories → build → review) остаётся BMAD; модуль подмешивает 1С-правила в контур setup / build / review. Не вторая методология, не замена BMAD.
- **Статус:** закрыт · 2026-08-24

### Q6. Живой контракт MCP vs версионируемый playbook
- **Суть:** см. развёрнутое объяснение в [notes.md](notes.md). Кратко: копировать описания инструментов EDT-MCP в модуль = вечная рассинхронизация с релизами плагина; источник правды об инструментах — живой сервер (`tools/list`, `get_tool_guide`) + пакет `rules/`+`agent/` плагина, обновляемый синхронно с ним.
- **Рекомендация (гибрид «двух темпов»):** модуль версонирует только медленный слой (принципы, гейты, BSL-практики, процесс); быстрый слой (имена/параметры инструментов, правила вызова) не версонирует вовсе.
- **Статус:** открыт, ждёт подтверждения · 2026-08-24
